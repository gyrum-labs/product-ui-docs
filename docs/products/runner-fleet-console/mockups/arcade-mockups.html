01

The marble run

A wall-mounted marble run. Everything waiting sits in the bucket at the top; a gate opens and the marbles run down the slope into the next stage.

What this screen shows

One marble per pull request, coloured by the stage it is in. The bucket at the top of the slope is the intake: every pull request that is waiting to be processed sits in it. When a pull request's state changes, its marble leaves the bucket, a gate in the wall opens, and the marble rolls down the track to the collector at the end of the next stage.

The drum in the middle of the run is the test stage: marbles that roll into it are carried around by the paddles and dropped out the other side, which is what being tested feels like. A stage that needs work goes back up the return lift rather than down the slope, and the collector for each stage holds its marbles in a bowl with the count on the sign above it.

Reading it

The height of each stage's bowl is the honest size of that stage: a bowl full of marbles means a stage that is holding a crowd. A marble in flight is a pull request mid-transition.

Design notes

Language
cabinet-style marble run, side elevation
Sprites
glass marbles with a highlight and a soft shadow; steel channel with a double rail; paddle drum; enamel stage signs
Motion
gravity along the channel, constant roll speed, marbles settle into the bowl with a small bounce
Live
one marble per pull request; stage changes drive the motion
02

The heap

Boxes on belts. Each belt is as long as its stage is big, and the finished work piles up in a heap at the end.

What this screen shows

The delivery pipeline as a factory floor. Every pull request is a crate. A crate rides the belt of the stage it is in; the belt is drawn exactly as long as that stage is big, so a stage with eighty pull requests in it is visibly longer than a stage with none. A crate that changes state is lifted to the next belt up.

The heap on the right is the finished work. Crates that reach the last stage are tipped off the end of the belt and fall into the heap, where they settle under their own weight. The heap is the backlog that has been delivered and is still lying about.

Reading it

Long belt = big stage. A crate in the air is a state change in flight. The heap is the pile of work that is finished but not yet cleared away.

Design notes

Language
side-elevation factory line, arcade cabinet palette
Sprites
stencilled crates with a stage stripe; roller belts with a tread pattern; a tipping chute; a settling heap
Motion
belts run at a constant speed; crates hop between belts on a short arc; the heap settles on landing
Live
one crate per pull request; belt length is drawn from the live count
03

The city

A top-down city. Every stage is a district, and every pull request is a resident who walks between districts when their situation changes.

What this screen shows

The fleet as a city seen from above. Each stage is a district, and the district's size is drawn from the number of pull requests in it: a district with many residents has bigger blocks and taller buildings. The residents stand outside the building of their stage, so the crowd outside a building is that stage's backlog, read at a glance.

When a pull request's state changes, its resident walks — out of the district, along the pavement, across the crossing, into the next district. The walk is the change; nothing teleports. The industrial plant in the south-west is the single heavy test slot: it is loaded while a run holds it, and it is the only way onto the heavy lane. The car park in the north-east is the runner pool — one car per runner, and a car leaves the park when its runner picks up work.

Reading it

Residents walking are pull requests mid-transition. A district emptying faster than it fills is work moving forward. Street lights come on at dusk by the real clock.

Design notes

Language
top-down city plan, tile grid, 1990s city-builder palette
Sprites
district blocks with roofs, roof plant and drop shadows; pavement and crossing stripes; residents; cars; street lamps; the plant's chimneys
Motion
residents walk the pavement; cars follow the streets; lamps light at dusk; the plant's smoke drifts
Live
one resident per pull request; block size is drawn from the live count
04

Pinball board

The pipeline as a pachinko board. Each stage is a band, and a band is as tall as that stage is big.

What this screen shows

A vertical board. The board is cut into seven horizontal bands, one per stage, and the height of each band is drawn from the number of pull requests in that stage — so the board itself is a picture of the shape of the work. A stage with nothing in it is a thin band; the stage holding eighty pull requests is a wide slab of board.

Each pull request is a ball bouncing in its band between the pegs. A ball whose state changes drops through the gate at the bottom of its band into the next one, and the pegs make it scatter on the way down.

Reading it

The band heights are the stage sizes. Balls in flight between two bands are state changes happening. A ball bouncing a lot is a busy stage, not a stuck one.

Design notes

Language
pachinko / pinball board, backlit and slightly dusty
Sprites
chrome balls with a specular highlight; peg lattice; drop gates; band rails with the stage name engraved
Motion
real gravity and peg deflection; balls settle in their band with a gentle roll
Live
one ball per pull request; band heights are drawn from the live counts
05

Production line

Seven machines down a factory floor. A machine is as tall as its stage is big, and the work rides the belt through it.

What this screen shows

Each stage is a machine on the line. The machine's height is the size of the stage — a stage holding a crowd of pull requests is a tall machine with a full output tray, and a stage with nothing in it is a stub. The belt runs through every machine, and the work is the crates riding it.

A crate that changes state is lifted to the next machine's tray by the overhead arm. The machine's own readout shows the live count and whether the heavy gate has run for it.

Reading it

Tall machine = big stage. The belt is the order of work, left to right. The heavy-gate lamp on each machine is the truth about whether that stage has ever been tested.

Design notes

Language
arcade factory side view, machine silhouettes on a dark floor
Sprites
machine bodies with a lit readout, an output tray and a warning lamp; crates; the overhead transfer arm; floor markings
Motion
belt tread scrolls; the arm swings and sets a crate down; lamps blink on state change
Live
one crate per pull request; machine height is drawn from the live count
06

Arcade cabinets

A song-select screen. Every stage is a cabinet, and a cabinet is as tall as its stage is big.

What this screen shows

The pick-a-stage screen from a rhythm game, with the real pipeline in it. Each stage is a cabinet standing on the floor of the arcade, and the cabinet's height is the size of that stage — a stage holding eighty pull requests is a cabinet that reaches the ceiling. The marquee on top carries the stage name, and the cabinet's screen carries the live count.

The panel on the right is the preview: the stage you have selected, the pull requests in it, and the fleet's high score — the throughput the fleet is holding right now. Selecting a cabinet is what the pointer does; nothing here is decoration, every panel is a live number.

Reading it

Cabinet height = stage size. The marquee lamps chase along the selected cabinet. The preview panel lists the actual pull requests in the selected stage.

Design notes

Language
arcade cabinet select screen, CRT curvature and scanlines
Sprites
cabinet bodies with lit side art, marquees, a screen with a live count, a preview panel and a high-score table
Motion
marquee lamps chase; the selected cabinet pulses and the preview switches; the screen flickers faintly
Live
one cabinet per stage; cabinet height is drawn from the live count
